실무 Spring 백엔드에서 Codex 와 Claude 를 매일 쓰다가 질문이 생겼다.

AI 리뷰어가 내는 품질 숫자 중 얼마가 모델의 것이고, 얼마가 측정 선택의 것인가?

Claude Code 와 Codex CLI 에게 증명 가능하게 안전한 코드와 가드만 지운 짝을 리뷰시키고, 같은 지적을 채점 정의 · 매칭 허용 오차만 바꿔 다시 채점했다. 아래 그림은 모두 uv run codeproof report 가 만드는 생성물이다.

점수판

숫자 중 얼마가 측정 선택인가

AI 에이전트와 만든 방식

이 저장소도 Claude Code 와 함께 만들었다 — PR 병합 커밋을 뺀 모든 커밋에 공동 작성 표시가 있다.

  • 확인 수단을 먼저 준다 — 테스트 · 반증 시나리오 · verify.sh 로 일이 통과 · 실패로 끝난다.
  • 사람은 기준과 경계를 정한다 — 무엇을 재고 무엇을 주장하지 않을지, 데이터를 보기 전의 측정 절차, push · 병합 · 유료 실행처럼 되돌릴 수 없는 일.
  • 꼭 지켜야 하는 규칙은 코드로 강제한다 — 문서에만 적은 규칙은 지켜지지 않았다. 테스트 · 편집 훅이 막는다.
  • 쓴 쪽이 채점하지 않는다 — 다른 문맥의 독립 검토와 다른 모델 패밀리(Codex)의 감사가 라벨을 다시 본다.

테스트가 초록인 채로 틀렸던 자리와 그것을 잡은 방법

받아서 돌려 보기 — API 키 없이

git clone https://github.com/manners-parkpro/codeproof-ai.git
cd codeproof-ai
uv sync
uv run pytest
./scripts/verify.sh

필요한 것은 git 과 uv 뿐이다. verify.sh 는 위 주장이 이 기계에서 재현되는지, 테스트가 공허하지 않은지 (불변식을 일부러 깨고 테스트가 우는지) 본다.

그림의 숫자는 생성물이다 — 손으로 고치지 않고, 테스트가 최신인지 본다.
