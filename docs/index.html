안전한 파이썬 코드와, 거기서 안전장치 하나를 지우거나 우회한 버그 코드를 짝으로 만들어 두 AI 에게 리뷰시켰다. 버그 쪽만 짚어야 정답이다.

린터(Ruff) 경고를 두 채점 규칙으로 세면

45.7배

린터는 같은 코드에 늘 같은 경고를 낸다 — 그 경고를 Qodo 벤치마크처럼 「결함 없는 코드의 경고는 전부 헛경고」로 세면 777건, 「안전하다고 증명한 범위 안을 버그라 한 것」만 세면 17건이다 (전체 규칙). 보안 규칙만 고르면 8 대 8로 같다.

버그를 짚은 비율(헛경고는 따지지 않음)은 몇 줄 차이까지 같은 지적으로 치느냐에 따라

둘 다 오르고, 차이는 남는다

결함 줄과 겹친 지적만 인정하면 Claude Code 69.6% · Codex CLI 47.6%, 근처 10줄까지 인정하면 Claude Code 88.4% · Codex CLI 70.0%. 예: D140 에서 Codex CLI 는 3회 모두 결함 근처를 가리켰지만 「놓침」으로 셌다 — 2줄만 넓혀도 「짚음」이다.

대신 헛경고는

7.1% 대 2.0%

안전하다고 증명한 범위를 버그라 한 비율은 Claude Code 가 더 높았다. 많이 짚는 쪽이 헛경고도 더 냈다.

주 지표는 「버그만 정확히 짚었다」 하나이고, 무엇을 주장할지와 함께 데이터를 보기 전에 정했다. 위 카드 가운데 린터 카드는 채점 규칙의 몫을 Ruff 로 잰 값이고, 두 AI 의 카드는 같은 판정을 다시 묶은 보조 지표다. 숫자와 문장은 uv run codeproof report 가 만든다 — 결과 · 근거 · 한계. 이 저장소도 Claude Code 와 함께 만들었다 — 만든 방식.

직접 해 보기

두 AI 가 실제로 남긴 리뷰를 짝마다 열어 보거나, 내 코드를 붙여 넣어 린터가 무엇을 보는지 확인한다. 설치도 API 키도 필요 없다.

코드는 브라우저 밖으로 나가지 않는다. 처음 한 번 Ruff(WebAssembly)를 받고, 받은 파일은 해시로 검증한다.

내 컴퓨터에서 같은 화면을 열면 Claude Code 나 로컬 모델(Ollama)이 리뷰하고, 지적마다 인용이 그 줄에 있는지 · 린터도 같은 곳을 짚었는지 근거가 붙는다. API 키는 필요 없다.

AI 에이전트와 함께 만든 방식

이 저장소도 Claude Code 와 함께 만들었다 — PR 병합 커밋을 뺀 모든 커밋에 공동 작성 표시가 있다. AI 에게 맡기되, 끝났는지는 AI 의 말이 아니라 검사로 판정한다.

  • 확인 방법부터 만든다맡기기 전에 테스트와 「일부러 망가뜨려 보는 시나리오」를 먼저 둔다. 그래서 일이 통과 · 실패로 끝난다.
  • 기준은 사람이 정한다무엇을 재고 무엇을 주장하지 않을지는 데이터를 보기 전에 정한다. 공개 · 병합 · 유료 실행도 사람이 정한다.
  • 결과를 원본으로 다시 본다테스트가 통과해도 원본 지적을 다시 읽는다. 위의 「놓침」 사례도 그렇게 찾았다.
  • 쓴 쪽이 채점하지 않는다다른 대화의 독립 검토와 다른 회사 모델(Codex)이 결과를 다시 본다.

실제 사건 — 테스트가 모두 초록인데 틀렸던 자리

AI 지적을 검증하는 코드가 짧은 예제에서만 쓰이다가 실제 코드를 처음 만나자, 「인용한 코드가 그 줄에 없다」는 판정이 정확한 인용에도 붙고 있었다. 여러 줄 인용을 한 줄씩 대조한 탓이었다. 고친 뒤 같은 측정 묶음에서 그 오류는 사라졌다.
